# Диагностика профиля на записи обхода

После проверки топиков, типов и TF запустите явную команду из корня MGTS в Windows PowerShell. Нужна запись с PointCloud2, профиль обхода и новый путь для JSON. Если организаторы выдали LaserScan, сначала преобразуйте его по памятке приёма. Проверка не требует готовой карты, эталона или инспекции. Предложенные поправки записываются только в диагностический отчёт.

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
& $python -X utf8 -m mgts_nav.self_check data/mapping --config configs/official-map.json --out out/check-01.json --max-scans 150 --budget 60 -q
$LASTEXITCODE
```

| Код | Интерпретация |
|---|---|
| 0 | На проверенных гипотезах не найдено противоречия. Для отдельных датчиков возможен статус `not_measured`. |
| 1 | Есть гипотеза о расхождении. В `checks` приведены исходные показатели и предложенная поправка. |
| 2 | Ошибка входа, параметров или записи отчёта. Выберите новый путь для результата. |
| 3 | Недостаточно привязок или длительности наблюдения, либо бюджет закончился до завершения перебора без выявленного предупреждения. |

`mirror` сравнивает исходную установку с креном +180°. `tilt` перебирает дополнительные повороты в системе base и сравнивает повторные попадания лидара в участки карты с прохождениями свободных лучей. Порог прироста оценки 0,04. В отчёте указаны число проверенных гипотез и `complete` для перебора; бюджет ограничивает начало очередной оценки, уже начатая операция может завершиться позже. Длинные записи прореживаются с указанным в отчёте шагом, поэтому результат зависит от покрытия.

`yaw` требует одометрии и поступательного движения. `clock_imu` и `clock_odom` используют корреляцию угловых скоростей и требуют поворотов; отсчёты гироскопа с признаком отсутствующего измерения пропускаются. Смещение может отражать задержку сенсора, ошибку траектории или вклад самой одометрии в прогноз ICP. Отчёт не даёт статистической вероятности правильности поправки. Сверяйте гипотезу с независимой калибровкой, TF или повторной записью, прежде чем менять рабочий профиль.

## Плоскость пола и TF

На ровной площадке дополнительная команда подбирает плоскость по низким точкам первых десяти сканов. Проверьте долю точек плоскости, её высоту и углы подъёма. Малое покрытие, наклонный пол или наклон корпуса ограничивают интерпретацию. Для плоского сканера пол может вообще не наблюдаться. Отдельно можно получить преобразование лидара из статического TF без IMU.

```powershell
& $python -m mgts_nav.calibration data/mapping --floor configs/official-map.json
& $python -m mgts_nav.calibration data/mapping --base base_footprint --lidar os_lidar
```

## Измеренные контроли

| Вход | Результат CLI |
|---|---|
| Штатное офисное демо и штатная поставка C из №122 | Код 0 в обоих случаях, по 67/67 поз с привязкой или началом. Согласованность 0,941 и 0,973. |
| C, добавлен тангаж −20° в base | Код 1, `tilt`. Согласованность 0,499 → 0,985. Предложены крен −2° и тангаж +20°. Наклон подобранной плоскости пола вырос с 0,09° до 9,42°, её поддержка упала с 27,2% до 2,8%. |
| Офисное демо, добавлен курс +10° в base | Код 1, `yaw`, предложена поправка −11,3°. |
| Поставка D, удалён известный поворот лидара вверх ногами | Код 1, обнаружен крен 180°. Согласованность 0,070 → 0,972. Одновременно обнаружен лаг одометрии +0,265 с. |
| D, исходная установка лидара, добавлено +0,25 с к времени одометрии поверх исходной задержки | Код 1, лаг +0,515 с; предложенное итоговое смещение профиля −0,265 с. |
| Один выбранный скан | Код 3, `not_measured`. |

Метод и исходная реализация принадлежат M1hairu. На публичной HEAP-1 в №83 штатный профиль дал предупреждение по часам IMU, внесённый тангаж +12° — дополнительное предупреждение по наклону. Для истинной задержки IMU внешний эталон отсутствует.
