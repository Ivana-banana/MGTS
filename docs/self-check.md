# Самопроверка профиля без эталона

На репетиции финала ([PR #35](https://github.com/Ivana-banana/MGTS/pull/35)) две ошибки прошли без сигнала. При перепутанном знаке наклона лидара сопоставились 100 % сканов, а ATE составила 0,26 м. Сдвиг часов одометрии на 0,25 с не назвал ни один инструмент до построения карты. `mgts_nav.self_check` ищет такие ошибки по самой записи обхода, без эталона и без готовой карты.

## Запуск

Из корня MGTS в Windows PowerShell, после построения первой карты:

```powershell
python -m mgts_nav.self_check data/mapping --config configs/official-map.json --out out/self-check-01.json --suggest-profile configs/official-map.checked.json
```

| Код выхода | Значение |
|---|---|
| 0 | `verdict: no inconsistency found` — расхождений нет |
| 1 | Найдено расхождение. Строки `MIRROR`, `TILT`, `YAW`, `CLOCK` называют поправку. `--suggest-profile` записывает профиль с ней |
| 2 | Ошибка входа: профиль, топики, кадры |

Пример вывода для сценария c с перепутанным знаком наклона:

```text
claimed profile: 100/100 scans matched, map consistency 0.496
TILT: extra roll +0.0 pitch +20.0 deg raises map consistency 0.496 -> 0.973
verdict: WARNING tilt; check the suggested profile before mapping (61.5 s)
suggested profile: out/e2e/c_fixed.json (rebuild the map and compare before use)
```

Ключ `-q` скрывает строки по отдельным кандидатам. `--budget` ограничивает время перебора наклона, по умолчанию 60 с. Если бюджет кончился, вывод сообщает об этом, а отчёт содержит `complete: false`. `--max-scans` ограничивает число сканов, по умолчанию 150. Более длинная запись прореживается равномерно. JSON-отчёт содержит для каждой проверки статус `ok`, `warning` или `not_measured` с причиной, числа, на которых основан вывод, и итоговые `suggested.base_from_lidar_xyzw`, `suggested.header_offset_s`, `suggested_lidar_rpy_deg`.

Поправка — это гипотеза, а не доказательство. Перед использованием постройте карту с предложенным профилем в новый каталог и сравните её с первой картой: стены должны стать тоньше, а дуги и пятна от пола должны исчезнуть. Ту же поправку внесите в профиль инспекции.

## Что проверяется

Запись читается в память один раз. Для каждой гипотезы вызываются те же `bag.scans()` и `slam.track()`, что в `map`. Occupancy-сетка не строится, поэтому одна гипотеза занимает 0,3–1,5 с.

**Согласованность карты.** Точка скана считается согласованной, если выполнены оба условия:
- рядом, в пределах 0,10 м, есть попадание скана, сделанного не менее чем на 4 с раньше или позже;
- её ячейку 0,1 м не «просветило» больше сканов, чем попало в неё. Просвет — свободная часть луча, которая заканчивается за 0,3 м до точки.

При неверном наклоне пол или потолок попадает в срез высот. Если ложная стена движется вместе с роботом, её не видно с других мест. Если пол заливает площадь, её просвечивают другие лучи. Сравнение просветов с попаданиями сохраняет настоящие стены, которые в коридоре видны под скользящим углом. Простой признак «просвечено хоть раз» давал на всех пяти коридорах ложную тревогу.

| Проверка | Как | Порог тревоги |
|---|---|---|
| Зеркало: лидар вверх ногами | Строится гипотеза с дополнительным креном 180°. Она должна дать согласованность выше, или лидар должен поворачивать против одометрии и IMU (корреляция скоростей курса ≤ −0,5) | Выигрыш ≥ 0,04 |
| Наклон: крен и тангаж | Тангаж −20…+20° через 5°, затем крен, затем компасный поиск по обеим осям с шагом 4° и 2° | Выигрыш согласованности ≥ 0,04 |
| Курс лидара | Направление перемещения за 1 с в системе базы по лидару и по одометрии. Учитывается плечо лидара: при ошибке курса траектория «базы» — это путь точки t − R(−e)·t | \|e\| ≥ 3,5° |
| Часы одометрии и IMU | Лаг с максимальной корреляцией скоростей курса лидарной траектории и датчика, как в `tools/clock_lag.py` | \|лаг\| ≥ 0,05 с при корреляции ≥ 0,7 |

Наклон, при котором лидар смотрит ещё ниже в пол, только выбрасывает дальние точки, и согласованность почти не меняется. Поэтому из значений в пределах 0,005 от лучшего берётся то, которое сохраняет больше согласованных точек.

## Ограничения

- Наклон виден, только если неверный наклон вносит в срез высот пол или потолок. Для лидара, который не видит ни того, ни другого (уровневый 2D, демо), ошибка тангажа до ±5° лишь выбрасывает часть точек. Проверка такую ошибку не называет, на карте она тоже почти не видна. Ошибки меньше ~4–5° не ловятся из-за порога 0,04.
- Величина наклона определяется с точностью ±3°. В сторону «ещё ниже в пол» у согласованности плато, и оценка может уйти туда на 2–3°.
- Курс в данных генератора смещён на +1,3–1,4°. Позиционный и угловой дрейф одометрии в генераторе различаются, и курс −8° определяется как +6,6°. С настоящей колёсной одометрией смещение будет своим. Без одометрии курс не проверяется (`not_measured`).
- Для часов и зеркала нужны повороты на обходе. Без поворотов — `not_measured`. Точность часов ±0,03 с, оценка занижена примерно на 0,015 с, потому что прогноз по одометрии притягивает ICP.
- Зеркало исправляется креном 180°. Для плоского скана крен 180° и тангаж 180° различаются на курс 180°, его называет проверка курса.
- Ошибки переноса (xyz) лидара, масштаба одометрии и наклона IMU не проверяются.
- Для 16-лучевого лидара перебор занимает 45–60 с и может упереться в `--budget`. Тогда отчёт содержит `complete: false`.
- Проверено только на синтетических записях на Linux. Под Windows не запускалось.
