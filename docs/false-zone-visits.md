# Ложные посещения соседних зон в офисном демо

При полном обзоре штатный отчёт не зарегистрировал ни одного посещения 12 контрольных зон на пяти реализациях шума. При ограничении обзора до 3 м он зарегистрировал шесть полностью ложных посещений на четырёх из пяти реализаций. Суммарная длительность — 1,4 с по 20 меткам. Самое длительное ложное посещение продолжалось 0,8 с.

## Геометрия и критерий

Для доли маршрута u от 0 до 1 эталонная инспекция имеет координаты x = −1 + 3u и y = 0,55 + 0,75 sin(πu), с остановками на концах. От каждого из четырёх экстремумов x или y наружу отложены три расстояния: 5, 20 и 50 см. На каждом расстоянии построена прямоугольная зона толщиной 10 см. Проекция зоны вдоль стороны покрывает весь диапазон второй координаты плюс 25 см с обоих концов. Поэтому непрерывная траектория достигает указанного минимального расстояния до каждой зоны и целиком лежит снаружи. Вершины записаны в JSON результата. [Протокол до прогона](https://github.com/Ivana-banana/MGTS/issues/116#issuecomment-7149217199)

Для каждого seed использованы те же данные, карта и известный старт, что в №47. Между прогонами менялся только фильтр обзора: в варианте 3 м сохранены точки с нормой XY в осях корпуса до 3 м включительно. На каждом маршруте 100 меток через 0,1 с. Стандартный visits принимает как минимум две последовательные метки matched внутри полигона при max_gap=0,25 с. Длительность вычисляется от первой до последней подтверждённой метки. Ни одна эталонная метка не попала ни в один полигон.

Для seed 101 посещений не зарегистрировано. Для остальных девяти полигонов число ложных интервалов равно нулю во всех десяти прогонах. Внутри каждого прогона интервалы разных зон по времени не пересекались. Один и тот же восточный полигон с отступом 50 см дал ложное посещение на четырёх реализациях. Пять seed меняют шум и выпадения измерений на одной геометрии и одной траектории; по ним нельзя оценить частоту ложных посещений в других помещениях.

## Воспроизведение

Из корня MGTS в Windows PowerShell. Первый шаг создаёт данные в новом каталоге.

```powershell
$p = '.\.venv-mgts\Scripts\python.exe'
& $p -m tools.evaluate_motion_disagreement out/office-controls-116 --pr-office
& $p -m tools.evaluate_false_visits out/office-controls-116
& $p -m pytest -q tests/test_zones.py
```

Два прогона по каталогам out/disagreement-47-pr и out/issue115-fresh дали побайтово одинаковые JSON при сохранении через Set-Content -Encoding utf8 в локальном PowerShell. SHA-256 — 66b3916051bcb38ed49e05ea58764c707330d1a7318e42f624aaa8b040e658b2.
