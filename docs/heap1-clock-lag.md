# Оценка сдвига часов IMU на открытых окнах HEAP-1

Проверен tools/clock_lag.py из PR №35, commit `997f7becc0f7806b0035e19789bc855c3e248541`, blob `04d13ec3937d005219403381d3fc271b6fd8eaea`. Использованы открытые полевые записи ETH Zürich GrandTour, ранее подготовленные для проверок HEAP-1. Независимое измерение истинной задержки между датчиками отсутствует.

Штатный track использует gyro_delta в прогнозе позы. Поэтому для опорных траекторий профиль отключает IMU и одометрию уже при чтении bag. Начальная поза локального обхода равна нулю. Из реализации PR без изменений вызваны trajectory_rate, sensor_rate и estimate. Гироскоп повёрнут в систему корпуса штатной калибровкой. На каждом окне взяты измерения между первой и последней метками сканов; к временам выбранных измерений добавлено 0, −200 и +200 мс. Поиск по ±1 с, шаг 5 мс, интерполяция 10 мс, max_hole 0,15 с. [План до измерения](https://github.com/Ivana-banana/MGTS/issues/60#issuecomment-7147737649).

¹ Из двух поз получается одна оценка угловой скорости. Вычислить корреляцию нельзя. В локальных обходах первый скан имеет статус origin и используется предложенным trajectory_rate.

После отказа локального обхода на инспекции с поворотом 38° сделана отдельная попытка привязки обеих инспекций к карте, построенной только по LiDAR кадров 150–189. Для неё использована первая поза CPT7 как известный старт. Последующие позы CPT7 использованы только для описания размаха движения. [Условия дополнительной проверки](https://github.com/Ivana-banana/MGTS/issues/60#issuecomment-7147755425).

На трёх пригодных опорах внесённый сдвиг передвинул максимум корреляции ровно на соответствующие ±200 мс. Для коррекции профиля при исходном нулевом offset нужно брать противоположный знак lag. Перенос максимума ожидаем при сдвиге всей временной оси и подтверждает знак относительной реакции. Абсолютную синхронизацию он не проверяет. На самом выраженном повороте недостаточно независимых лидарных привязок. Почти неподвижное окно дало корреляцию 0,854 при СКО гироскопа всего 0,251°/с; смена способа построения опоры изменила корреляцию до 0,560. Поэтому высокий пик на этих коротких окнах недостаточен для уверенной аппаратной калибровки. Ошибочность конкретного абсолютного значения без независимого эталона не установлена.

Воспроизведение из корня MGTS в Windows PowerShell, с подготовленными публичными bag и новым выходным каталогом:

```powershell
git fetch origin refs/pull/35/head
& .\.venv-mgts\Scripts\python.exe -m tools.heap1_clock_lag out/heap1-revisit-v2 out/heap1-heldout-37 out/clock-lag-repeat
```

Сценарий читает указанный Git-объект, сверяет blob, сохраняет его точные байты в каталоге эксперимента и пишет опорные CSV и report.json. Для воспроизведения нужен зафиксированный commit в локальной базе Git.
