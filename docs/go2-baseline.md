# Базовый прогон Go2 на записях финала

Обе записи используют один [профиль](../configs/go2-official.json). Команды из корня MGTS в PowerShell с Python проекта. Каталог результата должен быть новым.

```powershell
$py = '.\.venv-mgts\Scripts\python.exe'
foreach ($route in 'mapping','inspection') {
    & $py -m mgts_nav inspect "data/official/$route"
    & $py -m mgts_nav.profile "data/official/$route" --lidar /utlidar/cloud_base --odom /utlidar/robot_odom --verify-frames
    & $py -m mgts_nav.sync "data/official/$route" --config configs/go2-official.json
}
& $py -m mgts_nav.solve data/official/mapping data/official/inspection --config configs/go2-official.json --map-cache out/issue6/go2-cache --initial 0 0 0 --out out/issue6/go2
& $py -m mgts_nav.solve_audit data/official/mapping data/official/inspection out/issue6/go2
```

У шести стандартных потоков метки заголовков строго возрастают. На всех выбранных сообщениях кадры постоянны. Время получения и время заголовка относятся к разным шкалам. Медиана разности для cloud_base равна 80,893 с на обходе и 80,898 с на инспекции. Для согласования используются метки заголовка. При пределе интерполяции 0,1 с одометрия покрывает 1686/1688 и 1524/1525 сканов. Пропуски предшествуют первой одометрии. Наличие одометрии к моменту доставки скана исследуется отдельно в #194.

Лидарные точки уже выражены в корпусе. Для кинематики используется robot_odom. В обеих записях отсутствуют TF и камера. Поворот IMU относительно корпуса не подтверждён, поэтому канал выключен. Для пользовательского LowState проверен инвентарь, внутренние поля для этого прогона не требуются.

## Карта и траектория

Прогон строит двумерную сетку 0,08 м по высотному срезу 3D-лидара и использует явно заданный старт инспекции [0, 0, 0]. Это условие сравнения. Физическую позу старта и точность траектории предстоит проверить независимо. Попытка с той же картой и `--start-search delayed-keyframes` завершилась отказом из-за недостатка принятых глобальных гипотез.

| Показатель | Обход | Инспекция |
|---|---:|---:|
| Строк траектории | 1688 | 1525 |
| Начало карты / успешные сопоставления / только прогноз | 1 / 1687 / 0 | 0 / 1250 / 275 |
| Конечная поза x, y (м), yaw (рад) | 4,514; −0,792; 4,615 | −2,188; 10,076; 3,046 |
| Статус последней позы | matched | prediction_only |

При одинаковом старте срез от +0,15 до +1,5 м дал 93 сопоставления инспекции. Срез от −0,15 до +1,5 м дал 1250. В шести сканах от 40,355 до 40,750 с медианная высота точек составила от −0,303 до −0,288 м. На выбранном срезе все шесть сканов прошли ICP, доля согласованных точек составила 0,484–0,729. Самая длинная серия прогноза приходится на последние 129 сканов, от 100,601 до 109,737 с. Все 275 отказов в инспекции относятся к ICP. Принятая привязка показывает внутреннее согласие с картой, абсолютная ошибка без независимого эталона неизвестна.

В каталоге результата лежат карта PGM/YAML, обе траектории CSV, итоговые позы и статусы в summary.json и запись RViz. Аудит сверил обе траектории с метками сканов, карту и все 17 663 экспортированные позы с выходными файлами. Штатный одометрический baseline требует одометрии на первом скане и выдаёт причину пропуска в baseline-status.txt. Независимого эталона в поставке нет. Задачи #183, #184 и #188 охватывают воксельную карту, 3D-трекинг и автоматический старт.
