# Отложенный выбор и свободное пространство при глобальном старте

На трёх отложенных окнах HEAP-1 сочетание двух признаков приняло один старт (35,8 см, 1,03°), остальные варианты отказали во всех трёх. На первом окне 2560 отказали все. Отдельно проверены чужая карта, два одинаковых участка на одной карте и коридор с ограниченной дальностью. В этих трёх контролях ложных принятий не было. Одного успеха на почти неподвижном повторном визите недостаточно для включения в основной CLI.

В таблице В означает верный старт, О — отказ, Л — ложное принятие. Число — процессорное время в секундах, включая подготовку сканов. Односкановые методы получают окно 0 с, последовательные используют данные до 2 с после старта. Все используют один и тот же ограниченный coarse-поиск. Базовый delayed выполняет три таких поиска, пространственные половины карты — до шести, экспериментальные варианты — один. Половины имеют перекрытие по одному метру с каждой стороны. Это пространственное разбиение отличается от прежнего разбиения по времени обхода. [Протокол до прогона](https://github.com/Ivana-banana/MGTS/issues/162#issuecomment-7160257839)

Метки long и heldout обозначают окна 2560 и 2620. Суффиксы 60 и 120 задают следующие смещения от 2620. Повторяющийся коридор использует 3 м видимости с индекса 30, удвоенная карта содержит две одинаковые копии офиса с неизвестной полосой между ними, чужая сочетает офисную запись и карту коридора. Единый глобальный сдвиг карты сохраняет все относительные расстояния и состояния лучей. Без внешнего ориентира такой сдвиг не обнаруживается.
