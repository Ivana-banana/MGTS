# Время и пиковая память map на длинном синтетическом обходе

На общем Windows-компьютере с Ryzen 5 5500U (12 логических процессоров, Python 3.10.10) штатная команда map с C++ DLL обработала 1000 сканов за 6,38 с, с Python — за 23,51 с. Максимальный рабочий набор процесса составил 76,55 и 77,93 МиБ соответственно. На обеих длинах SHA-256 файлов map.pgm, map.yaml и trajectory.csv попарно совпали между реализациями.

| Сканы | Реализация | Клетки с накопленными наблюдениями | Время map, с | Пик до экспорта, МиБ | Пик перед построением PGM, МиБ | Пик за весь процесс, МиБ | Экспорт в словарь, мс |
|---:|---|---:|---:|---:|---:|---:|---:|
| 200 | Python | 9 195 | 5,98 | — | 76,82 | 76,82 | — |
| 200 | C++ | 9 195 | 2,00 | 74,75 | 74,75 | 75,47 | 4,48 |
| 1000 | Python | 9 578 | 23,51 | — | 77,93 | 77,93 | — |
| 1000 | C++ | 9 578 | 6,38 | 76,55 | 76,55 | 76,55 | 4,58 |

**Источник.** Синтетический офис из tools/benchmark_length.py, seed 17, префиксы одной записи обхода длиной 20 и 100 с. Оба варианта для каждой длины читают один и тот же bag без прореживания, с разрешением карты 0,08 м. Более длинная запись добавила только 383 клетки. По этим данным нельзя оценить потребление памяти карты, охватывающей существенно большую площадь.

**Измерение.** Один свежий процесс на строку. Время включает запуск Python, чтение bag, трекинг, сохранение карты и траектории. Подготовка записей и сборка DLL выполнены заранее. Пиковый рабочий набор взят из GetProcessMemoryInfo в самом процессе. Замеры до преобразования C++-сетки в словарь и после него показывают исторический максимум на эти моменты. В обоих опытах экспорт не поднял этот максимум; это не измерение объёма временных аллокаций. Разницу менее 2 МиБ между реализациями по одиночным запускам нельзя считать устойчивым выигрышем. Сборка DLL имеет SHA-256 `30af35537adaafac1c4c7221178ab27baa25c6ff2124a9e0858509936148fa3f`.

Из корня MGTS в Windows PowerShell, с существующим результатом benchmark_length и заранее собранной DLL:

```powershell
& .\.venv-mgts\Scripts\python.exe -m tools.benchmark_grid_memory out/length-benchmark-02 out/native-grid/native_grid.dll out/grid-memory-repeat
```

Команда требует новый выходной каталог. В report.json сохраняются полные хеши, сведения о машине, замеры и число клеток. При несовпадении продуктов процесс завершается ошибкой.
