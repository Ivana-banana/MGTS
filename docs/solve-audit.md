# Проверка готового результата solve без эталона

Из корня MGTS в Windows PowerShell передайте исходные записи в порядке «обход, инспекция» и каталог результата:

```powershell
& .\.venv-mgts\Scripts\python.exe -m mgts_nav.solve_audit data/mapping data/inspection out/solution
```

Команда открывает файлы для чтения. Код 0 и JSON означают, что перечисленные ниже проверки прошли. При расхождении код 2 и сообщение указывают продукт или топик и причину.

- Для каждого входного bag используются профиль из solution/profiles, заданный топик лидара и его поправка часов. Каждая строка trajectory.csv должна соответствовать метке очередного облака. Проверяются число строк, счётчики статусов, статус последней строки и её поза относительно summary.json.
- Когда профиль инспекции включает одометрию, solve экспортирует continuous.csv. Его опорные позы со статусом matched сравниваются с исходной лидарной траекторией. При отключённой одометрии экспортируется сама trajectory.csv.
- Для каждой позы /pose и /path проверяются координаты, ориентация, время и система координат. Сверяются число сообщений, крайние метки и время записи сообщений RViz. Для /map проверяются разрешение, размеры, начало карты, время и все значения занятости с учётом порогов YAML и порядка строк PGM.

Проверка сравнивает сведения, которые представлены в нескольких продуктах. Ошибка положения, согласованно повторённая в CSV и RViz, может пройти. Две записи с одинаковым набором времён и кадров также могут быть неразличимы по этой проверке. Для идентичности входных байтов предназначен [SHA-256 манифест](solve-manifest.md).

На сохранённой демоинспекции seed 73 проверены 200 сканов обхода, 100 сканов инспекции и 280 поз плотного маршрута RViz от 250,035 до 260,000 с. Воспроизводимый тест создаёт два свежих solve (с одометрией и без неё), меняет порядок входных записей, удаляет строку CSV, подменяет координату одной опорной позы и одну клетку PGM:

```powershell
& .\.venv-mgts\Scripts\python.exe -m pytest -q tests/test_solve_audit.py
```
