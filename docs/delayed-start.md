# Поиск стартовой позы по началу инспекции

На открытой записи повторного посещения HEAP‑1 начальная поза восстановлена без кинематической одометрии и без подсказки о месте возврата. Ошибка старта относительно CPT7 составила **8,51 см и 0,82°**. Штатный локализатор с полученной позой сопоставил **60/60 сканов**, ATE XY RMSE — **4,82 см**. Для сравнения, на том же окне с заданной первой позой CPT7 ошибка траектории составляла 4,75 см. [Происхождение данных и привязка CPT7](public-data.md)

Эксперимент использует первые 51 скан инспекции (на HEAP‑1 около 5 с движения). Через каждые десять сканов выполняется независимый глобальный поиск на фиксированной карте обхода. Для первого скана поддержка 0,474 оказалась ниже штатного порога 0,55. Для остальных пяти она составила 0,581, 0,572, 0,553, 0,566 и 0,599. Между соседними сканами ICP восстанавливает относительное движение, используя доступное приращение курса гироскопа как начальное приближение. Каждая успешная глобальная привязка даёт отдельную оценку позы первого скана.

Для принятия нужны три успешных поиска, изменение ракурса минимум на 0,25 м или 10° и попарное согласие начальных оценок в пределах 0,20 м и 6°. Разрыв локальной цепочки приводит к отказу. Порог поддержки глобального поиска сохранён. Каждый из шести поисков ограничен собственным бюджетом из [эксперимента №11](coarse-start.md).

В независимом контроле из семи синтетических окон метод отказал семь раз. В эту группу вошли симметричный коридор, чужая карта, два окна с дальностью 3 м, а также офис и два коридора с полным обзором. На последних трёх окнах зарегистрированные позы разошлись с локальной цепочкой. Поэтому команда доступна для отдельного эксперимента, а штатный автостарт в офисе сохраняет прежний алгоритм. [Окна и причины отказов](delayed-start-controls.md)

## Повторить без эталона

Для полного решения выберите метод через `--start-search` в `localize` или `solve`. Значение `coarse` проверяет первый скан. Значение `delayed` использует попарное движение между сканами, а `delayed-keyframes` — привязку к локальным ключевым сканам. Сопоставление этих двух способов приведено в [опыте с ключевыми сканами](keyframe-start.md). Все режимы возвращают траекторию от исходной первой метки. Выбранный алгоритм и его диагностика записываются в `initialization` и `start_search` файла `inspection/summary.json`. При отказе причина выводится в stderr, каталог итогового решения не создаётся.

```powershell
$p = '.\.venv-mgts\Scripts\python.exe'
$d = 'out/heap1-revisit-v2'
& $p -m mgts_nav.solve "$d/mapping" "$d/inspection" --config "$d/profile.json" --start-search delayed --out out/heap1-blind-solve
```

На движущемся окне эта команда сопоставила все 60 меток с ATE 4,82 см. На почти неподвижном окне с кадра 2620 режим `delayed` отказал по изменению ракурса; режим `coarse` восстановил все 60 поз с ATE 4,16 см. Для синтетического офиса проверено получение всех 100 исходных меток в режиме `delayed-keyframes`. Отсутствие флага выбирает прежний штатный автостарт.

Подготовьте запись и карту по [инструкции HEAP‑1](public-data.md). Первая команда пишет позу только при принятии, в новый файл. Отказ возвращает код 3. Вторая команда локализует все сканы, включая начало инспекции.

```powershell
$p = '.\.venv-mgts\Scripts\python.exe'
$d = 'out/heap1-revisit-v2'
$map = 'out/heap1-revisit-map/map.yaml'
& $p -m mgts_nav.delayed_start "$d/inspection" "$d/profile.json" $map --pose-out out/start-heap1.json
if ($LASTEXITCODE -eq 0) {
    & $p -m mgts_nav localize "$d/inspection" --config "$d/profile.json" --map $map --initial-file out/start-heap1.json --out out/heap1-delayed-inspection
}
```

Для ретроспективной оценки добавьте к первой команде `--reference "$d/inspection-reference.csv"`. Эталон открывается после поиска и локализации.

## Три отрезка после первого опыта

Следующие окна по 60 сканов были [выбраны до прогона](https://github.com/Ivana-banana/MGTS/issues/37). Это соседние неперекрывающиеся отрезки одного визита ANYmal на HEAP‑1. Карта, профиль и пороги взяты из первого опыта. Все три слепые попытки завершились отказом из-за недостаточного изменения ракурса. При заданной первой позе CPT7 все 180 сканов привязались к карте.

| Кадры инспекции | Глобальные привязки | Макс. удаление от начала окна по CPT7 | Диапазон курса по CPT7 | Расстояние до маршрута карты | ATE с заданным стартом |
|---|---:|---:|---:|---:|---:|
| 2620–2679 | 6/6 | 3,56 мм | 1,59° | 1,168–1,172 м | 4,13 см |
| 2680–2739 | 5/6 | 3,44 мм | 2,19° | 1,168–1,169 м | 2,89 см |
| 2740–2799 | 6/6 | 1,38 мм | 1,03° | 1,168–1,169 м | 3,10 см |

Повторные уверенные совпадения при почти неподвижном корпусе дают мало новых сведений для проверки начальной позы. У слепого режима здесь три отказа и ноль выданных траекторий. Миллиметровые величины в таблице — изменение показаний GNSS/INS внутри окна. Они характеризуют этот контроль и включают погрешность опоры.

```powershell
$p = '.\.venv-mgts\Scripts\python.exe'
& $p tools/heap1_revisit.py out/heap1-heldout --held-out
& $p -m tools.heap1_holdout out/heap1-heldout out/heap1-revisit-map/map.yaml
```

Для нового набора записываются XYZ и IMU из той же опубликованной ревизии GrandTour; конвертер проверяет контрольные суммы лидарных блоков. Оценщик открывает оба опорных CSV после завершения всех трёх слепых попыток. Для каждого окна сравнение с известным стартом получает только первую опорную позу.

### Что даёт один скан на этих же окнах

Штатная команда `localize` без стартовой позы отказала на каждом из трёх окон. Поддержка одиночного поиска оказалась слабой, размер карты превысил лимит многосканового поиска. Экспериментальный [поиск от грубой сетки к точной](coarse-start.md) на первом скане принял две позы и отказался от третьей. Для каждой принятой позы штатный локализатор восстановил все 60 меток.

| Первый кадр | Одиночный поиск по грубой сетке | Ошибка стартовой позиции / курса | ATE инспекции |
|---|---|---:|---:|
| 2620 | Принят | 4,64 см / 0,12° | 4,16 см |
| 2680 | Отказ по слабой поддержке | — | — |
| 2740 | Принят | 3,94 см / 0,11° | 3,10 см |

У сравнения три зависимых окна из одного посещения. Оно показывает конкретные случаи, когда подтверждения по движению получить трудно, а один информативный обзор всё же позволяет найти старт. Для повтора скрипт создаёт три отдельных bag, сохраняя исходные измерения IMU, и вызывает обычный CLI. Все предсказания завершаются до чтения CPT7. Каталог результата должен быть новым.

```powershell
& .\.venv-mgts\Scripts\python.exe -m tools.heap1_stationary_start out/heap1-heldout out/heap1-revisit-map/map.yaml out/heap1-stationary-comparison
```
При отказе явного `--start-search` команды `localize` и `solve` выводят в stderr строку `Start search refused: ` с JSON. В ней указаны метод, причина и уже вычисленные показатели. У многосканового поиска массив `anchors` содержит индексы рассмотренных сканов, оценки поддержки и причины отклонения отдельных кандидатов. Если проверка остановилась ещё до глобального поиска, массив может быть пустым. Для сохранения диагностики добавьте к команде PowerShell `2> start-errors.txt`.
## Диагностика разрыва на старте

При отказе `Gap in the local scan chain` штатный `localize --start-search delayed` выводит в stderr объект `rejected_pair`. В нём указаны индексы первой неподходящей пары в стартовом окне (от нуля), обе метки заголовка после коррекции часов, интервал в секундах, количество пригодных точек каждого скана и список причин. `time_interval` означает интервал вне (0; 0,35] с, `too_few_points` — меньше 12 точек хотя бы в одном скане. У пары могут одновременно присутствовать обе причины.

На публичном окне инспекции Intel Lab первая пара содержит 109 и 107 точек при интервале 0,532869 с. Отказ происходит по времени ещё до глобального поиска. [Происхождение записи и подготовка окна](intel-lab.md)
