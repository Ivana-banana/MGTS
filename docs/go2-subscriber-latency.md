# Когда подписчик получает позу Go2

При воспроизведении официальной инспекции на 1× независимый ROS 2-процесс получил 1525 сканов и 1524 позы. Для 1524 пар с одинаковой меткой **p95 интервала между входами в callback скана и позы составил 33,62 мс**. Медианный период лидара равен 71,99 мс. Дольше одного такого периода заняла 21 пара из 1524 (1,38%). [Исходные показания наблюдателя, замеры callback повторного прогона и сводка](go2-subscriber-samples.zip).

| Измерение, мс | p50 | p95 | p99 | Максимум |
|---|---:|---:|---:|---:|
| Получение скана → получение позы независимым подписчиком | 17,95 | 33,62 | 77,20 | 238,12 |
| Вход в callback лидара → после publish у узла при том же повторе | 16,48 | 31,76 | 73,97 | 229,18 |
| Тот же внутренний интервал в опубликованном кандидате a5ad606 | 12,03 | 25,25 | 31,77 | 168,99 |

## Как измеряли

Один наблюдатель в отдельном процессе подписан на /utlidar/cloud_base (best effort) и /mgts/pose3d (reliable), глубина обеих очередей 100. На входе в каждый callback сохраняется time.monotonic_ns(). Ключ пары — целочисленные sec и nanosec из ROS Header. Интервал равен разности двух монотонных показаний наблюдателя. Он включает различия в доставке и планировании обоих callback, десериализацию и обработку скана узлом. Задержка до входа в callback скана у наблюдателя сокращает измеренный интервал. Два топика могут приходить в разном порядке, в частности поза может быть зарегистрирована раньше скана. В этом прогоне отрицательных интервалов не было. Из разности процентилей отдельных распределений нельзя вывести время транспорта после publish.

Сверены точные множества меток входного MCAP, выходной записи повтора и опубликованного результата. Без потерь у наблюдателя, повторов и лишних меток. Один скан (1795605722371275663 нс) остался без позы в обеих записях. В timings.csv этого повтора его статус missing_odometry. Все 1524 метки опубликованных поз воспроизвелись. Полный исходный журнал релиза имеет SHA-256 783c6f10b4a72ac2c820854f5b5cc61c93166d71708f72e114785de0fb154543.

## Воспроизведение

Windows 10 Enterprise LTSC 19044, AMD Ryzen 5 5500U (6 ядер, 12 потоков), 15,34 ГиБ доступной системе физической памяти. Нативный ROS 2 Humble, Python 3.14.10, rmw_fastrtps_cpp, только localhost, ROS_DOMAIN_ID=108. Использованы версии узла и replay из 6409cca с обычным единичным map ← odom и фиксированная карта опубликованного прогона. Это один запуск на общей машине. Числа описывают измеренный прогон, включая нагрузку в момент измерения.

Из корня MGTS в активированном [окружении ROS 2 Windows](go2-windows-ros.md) запустите в свободном домене. Нужен новый выходной каталог. Наблюдатель регистрирует подписки, запускает штатный replay отдельным процессом и дочитывает очереди после его завершения.

```powershell
$env:ROS_DOMAIN_ID='108'
$env:ROS_LOCALHOST_ONLY='1'
python -m tools.go2_subscriber_latency data/official/inspection out/issue197/full3d/map.npz out/issue208/repeat
```

Сверка в обычном Python-окружении MGTS с rosbags. Последний аргумент — каталог опубликованного прогона с result/ и timings.csv.

```powershell
.\.venv-mgts\Scripts\python.exe -m tools.go2_subscriber_audit data/official/inspection out/issue208/repeat out/issue197/live-full
```
