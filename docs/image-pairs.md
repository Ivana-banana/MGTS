# Визуальные пары из ректифицированных изображений ROS

`mgts_nav.image_pairs` читает один топик `sensor_msgs/Image` и записывает одну строку JSONL для каждой пары соседних кадров. Поддержаны `mono8`, `rgb8` и `bgr8`, включая отступ в конце строки. Достаточно зависимостей основного проекта.

Для своей камеры укажите размеры ректифицированного кадра в порядке ширина, высота, его оптический frame_id, матрицу K в пикселях и единичный кватернион поворота из оптической системы в базу в порядке x, y, z, w. Пример файла `camera.json` для синтетической проверки:

```json
{"size":[320,240],"frame_id":"optical","K":[[230,0,160],[0,230,120],[0,0,1]],"base_from_camera_xyzw":[-0.5,0.5,-0.5,0.5]}
```

```powershell
python -m mgts_nav.image_pairs data/inspection inspection-pairs.jsonl --topic /rect --calibration camera.json --header-offset-s 0
python -m mgts_nav.solve data/mapping data/inspection --config configs/official.json --inspection-visual-pairs inspection-pairs.jsonl --out result
```

Подставьте путь к своему профилю датчиков. Время каждой точки интервала равно `header.stamp + header_offset_s` в секундах на шкале лидара. Нулевое смещение подходит для уже согласованных часов. Для записи с независимо подтверждёнными границами передайте также `--camera-motion-bound-m` (максимальное перемещение центра камеры за любую соседнюю пару, включая пропуски кадров) и `--min-scene-range-m` (минимальная дальность статических ориентиров). Опущенная граница сохраняется как `null`; в таком режиме пары пригодны для диагностики, а визуальная поправка отклоняется.

Адаптер выделяет до 400 углов и ищет взаимно ближайшие нормированные фрагменты 11×11 пикселей с проверкой различимости совпадения. Он рассчитан на небольшие изменения ракурса между кадрами. Смаз, повторяющийся рисунок, движущиеся объекты и слабая текстура ограничивают точность. Ректификацию и синхронизацию часов выполняют заранее. Допуск пары определяют штатные `vision` и `visual_fusion`.

### Проверка

```powershell
python -m pytest -q -s tests/test_image_pairs.py
```

Тест записывает пиксели в ROS 2 bag, задаёт поворот проективным преобразованием и запускает конвертер через CLI. Для +2° получено +1,9955° (301 согласованная точка), для −2° получено −1,9929° (291 точка). На однотонном кадре получено 0 соответствий и отказ `too_few_tracks`. На текстурированных кадрах с пропущенными границами получен отказ `missing_motion_or_range_bound`. Эти измерения относятся к синтетическим изображениям 320×240.
