# HEAP-1: карта по 300 сканам обхода

На кадрах Velodyne 150–449 полевой записи ETH Zürich GrandTour штатный map построил карту с разрешением 0,08 м. Из 300 сканов первый задал начало карты, остальные 299 получили статус matched. За 29,90 с записи робот прошёл по CPT7 20,94 м, оценённая длина пути составила 21,10 м. Позиционная ошибка росла по ходу обхода, хотя каждый последующий скан сопоставился с картой.

| Кадры | matched / сканы | RMSE XY, см | RMSE курса, ° | Ошибка XY на последнем кадре, см |
|---|---:|---:|---:|---:|
| 150–249 | 99/100 | 17,28 | 0,424 | 30,86 |
| 250–349 | 100/100 | 38,26 | 0,713 | 46,08 |
| 350–449 | 100/100 | 53,43 | 0,681 | 62,70 |
| 150–449 | 299/300 | 39,23 | 0,620 | 62,70 |

Все ошибки посчитаны в общей системе первого кадра. Каждый отрезок включает свои 100 исходных меток. Использовались родной гироскоп ANYmal, штатный Python-бэкенд карты и единственный старт (0,0,0). Траектория CPT7 интерполирована на метки сканов для оценки; map и localize получали только bag, профиль и карту.

Полная команда map заняла 126,09 с, попытка localize — 13,78 с на общей Windows-машине. Карта PGM/YAML и CSV обхода побайтово совпали в двух запусках.

**Повторная инспекция.** На тех же кадрах 2560–2619 штатный localize с режимом delayed завершился кодом 2: `Fewer than three accepted global poses`. Поэтому траектория инспекции по длинной карте и её ATE отсутствуют. В контрольном повторе с прежней картой по 40 сканам тот же режим сопоставил 60/60 с ATE 4,82 см. Результат ограничен одной миссией, одной картой и одним инспекционным окном. [Исторический прогон](delayed-start.md)

**Совпадение входов.** В ROS 2 bag первые 40 лидарных сообщений обхода и все 60 сообщений инспекции совпали с историческим набором как по меткам заголовка и записи, так и по каждому байту сериализованного PointCloud2. SHA-256 профиля для обоих вариантов — `1637bebe6db4605e6ff5b62ec080100805f11357112eb30d8460fe48abb5da7a`. Адаптер читает прежнюю закреплённую ревизию набора af6b6dd6f91696f8ec8c98134e195514834911b2. [Источник и подготовка данных](public-data.md)

**Воспроизведение.** Два новых выходных каталога, Windows PowerShell из корня MGTS. Конвертер требует numcodecs. Без опции --long-mapping он по-прежнему выбирает кадры 150–189.

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
& $python tools/heap1_revisit.py out/heap1-long-data --long-mapping
& $python -m tools.heap1_long_mapping out/heap1-long-data out/heap1-long-result
```

В scores.json сохраняются длительности полных команд, метрики для всей карты и трёх отрезков, статус инспекции и текст отказа. Загрузка и преобразование исходных данных в длительности команд не входят. [План измерения, зафиксированный до запуска](https://github.com/Ivana-banana/MGTS/issues/80#issuecomment-7148220443)

## Где накапливается ошибка перемещения

Уже за первые 100 шагов расчётная конечная точка отклонилась от CPT7 на 31,67 см. Для каждого шага измеренное и опорное перемещения переведены в оси корпуса по соответствующему курсу в начале шага. Разность двух векторов повёрнута обратно в карту по измеренному курсу. Второе слагаемое показывает, насколько изменилось бы **опорное** перемещение при повороте по измеренному курсу вместо опорного. Сумма слагаемых за 299 шагов воспроизводит наблюдаемую конечную ошибку с погрешностью менее 10⁻¹⁴ м по каждой координате.

| Кадры и число шагов | Вклад ошибки перемещения, X/Y карты, см | Вклад ошибки курса, X/Y карты, см | Изменение ошибки положения, X/Y карты, см |
|---|---:|---:|---:|
| 150–250, 100 | −17,15 / +22,84 | −0,61 / +3,38 | −17,76 / +26,22 |
| 250–350, 100 | −12,04 / −1,82 | −3,97 / +6,56 | −16,00 / +4,74 |
| 350–449, 99 | −10,43 / +2,76 | −5,05 / +5,10 | −15,47 / +7,85 |
| Весь обход, 299 | −39,61 / +23,78 | −9,63 / +15,04 | −49,24 / +38,81 |

Два повтора расчёта заменяют по одному компоненту позы. С измеренными перемещениями корпуса и опорным курсом конечная ошибка составила **46,34 см**. С опорными перемещениями и измеренным курсом она составила **17,85 см**. Исходная ошибка равна **62,70 см**. Это послепроходный анализ уже рассчитанных поз. Изменение курса внутри самого ICP могло бы изменить и найденные перемещения.

Из 29 полных неперекрывающихся интервалов по десять шагов наибольшее расхождение относительного перемещения пришлось на кадры **220–230**. В осях корпуса в начале интервала оно составило −10,24 см по X и +2,43 см по Y, по модулю 10,53 см. Последние девять шагов входят в итоговую ошибку по маршруту. Для повтора передайте CSV обхода и соответствующий ему эталон. Пары меток сверяются с допуском 1 мкс. [Условия эксперимента](https://github.com/Ivana-banana/MGTS/issues/89)

```powershell
& $python -m tools.heap1_drift out/heap1-long-result/map/trajectory.csv out/heap1-long-data/mapping-reference.csv
```
## Высотный срез облака при повторном посещении

На карте из 300 сканов поднятие верхней границы среза с 1,50 до 2,50 м уменьшило RMSE обхода с 39,23 до 25,88 см. При повторном посещении с тем же срезом ICP отклонил все 60 сканов даже с известной стартовой позой. Выбор среза по одной ошибке обхода привёл бы здесь к потере локализации на инспекции.

| Высота в системе корпуса, м | RMSE обхода, см | Ошибка конца обхода, см | Автостарт delayed | Привязки инспекции с заданным стартом | RMSE инспекции, см |
|---|---:|---:|---|---:|---:|
| 0,15…1,50 | 39,23 | 62,70 | отказ | 60/60 | 32,62 |
| 0,15…2,50 | 25,88 | 41,45 | отказ | 0/60 | траектория отсутствует |
| −0,15…1,50 | 45,36 | 71,87 | отказ | 52/60 | 35,66 |

Во всех трёх обходах первая поза задала начало карты, остальные 299 сканов сопоставились. Для известного старта использована первая поза CPT7, для RMSE — все доступные позы решения на метках CPT7, включая восемь прогнозов в последней строке. Три карты построены одинаковым C++-ядром. У исходного среза PGM, YAML и CSV обхода побайтово совпали с ранее опубликованным контролем Python. Все прочие параметры профиля и разрешение 8 см сохранены. [План сравнения](https://github.com/Ivana-banana/MGTS/issues/91)

Для повтора создайте две копии `out/heap1-long-80/profile.json`, изменив в каждой только массив `height_band_m` по таблице. Для каждой копии выполните команды ниже с отдельными именами выходных каталогов. [Сборка DLL](native-grid.md)

```powershell
$data = 'out/heap1-long-80'
$python = '.\.venv-mgts\Scripts\python.exe'
$cfg = 'out/upper.json'
$map = 'out/upper-map'
& $python -m mgts_nav map "$data/mapping" --config $cfg --grid-dll out/native-grid-backend-25/native_grid.dll --out $map
& $python -m mgts_nav.metrics "$map/trajectory.csv" "$data/mapping-reference.csv"
& $python -m mgts_nav localize "$data/inspection" --config $cfg --map "$map/map.yaml" --start-search delayed --out out/upper-auto
$p = Import-Csv "$data/inspection-reference.csv" | Select-Object -First 1
& $python -m mgts_nav localize "$data/inspection" --config $cfg --map "$map/map.yaml" --initial $p.x $p.y $p.yaw --out out/upper-seeded
```
## Поиск старта на начальном участке карты

Для маршрута с известным возвратом в начальную зону проверен двухэтапный запуск. Поиск `delayed_start` получает карту первых 40 сканов обхода и первые сканы инспекции. Полученную позу принимает локализатор по полной карте из 300 сканов. На всех трёх картах нулевая поза соответствует одному сообщению лидара в 1731588427,081529 с. Проверены побайтовое равенство профилей датчиков, метки записи и SHA-256 всех первых 40 сообщений PointCloud2. Это позволяет передать координаты позы напрямую, хотя границы растров у карт различаются.

| Полная карта | Привязка инспекции | RMSE положения | Макс. ошибка положения | RMSE курса |
|---|---:|---:|---:|---:|
| Штатный обход | 60/60 | 32,44 см | 38,64 см | 0,807° |
| Обход с прогнозом скорости из №88 | 60/60 | 6,29 см | 11,08 см | 0,356° |

На кадрах инспекции 2560–2619 карта начального участка дала старт (1,0146 м, 1,3176 м, −0,02958 рад). Обе траектории рассчитаны до обращения к эталону CPT7. Прямой поиск на обеих полных картах в опыте №88 отказал. На почти неподвижных кадрах 2620–2679 поиск на начальном участке также отказал из-за недостаточного изменения ракурса, файл стартовой позы отсутствовал. При неизвестной зоне возврата выбор единственной начальной части карты требует отдельного обоснования. [Условия эксперимента](https://github.com/Ivana-banana/MGTS/issues/93)

Для повтора используйте карты из №80 и №88 и новый путь для файла позы. Следующая команда локализации использует полную карту с прогнозом скорости.

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
$data = 'out/heap1-long-80'
& $python -m mgts_nav.delayed_start "$data/inspection" "$data/profile.json" out/heap1-revisit-map/map.yaml --pose-out out/prefix-start.json
if ($LASTEXITCODE -eq 0) {
    & $python -m mgts_nav localize "$data/inspection" --config "$data/profile.json" --map out/heap1-velocity-88/map.yaml --initial-file out/prefix-start.json --out out/prefix-localized
}
```
## Поиск по всем участкам обхода

В отдельном опыте убрали подсказку о зоне возврата. Все 300 сканов обхода разбили по времени на семь частей по 40 сканов и одну из 20. Для каждой части построили свою сетку 8 см из исходных сканов и поз, полученных с прогнозом скорости. Все сетки используют общую систему координат полной карты. Для каждой запустили один и тот же `delayed` на первых 51 сканах инспекции. Условие до запуска разрешало выдать старт только при единственной принятой части. [План эксперимента №94](https://github.com/Ivana-banana/MGTS/issues/94)

На участке кадров 150–189 пять из шести кандидатов получили достаточную поддержку и согласовались с локальным движением. На остальных семи участках все кандидаты были отклонены. Найденная начальная поза в системе карты — (1,0800 м, 1,3192 м, −0,03652 рад). Штатный локализатор по **полной** карте подтвердил 60/60 сканов, RMSE составила **6,30 см по XY и 0,358° по курсу**, пик позиционной ошибки — 11,08 см. Эталон CPT7 читался только после поиска и локализации. Это одна проверка на том же возврате HEAP-1. Независимые проверки на повторяющейся геометрии собраны в [№95](https://github.com/Ivana-banana/MGTS/issues/95).

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
$data = 'out/heap1-long-80'
$full = 'out/heap1-velocity-88'
$sections = 'out/field-sections'
& $python -m tools.heap1_submap_start $data $full $sections --grid-dll out/native-grid-backend-25/native_grid.dll
if ($LASTEXITCODE -eq 0 -and (Test-Path "$sections/start.json")) {
    & $python -m mgts_nav localize "$data/inspection" --config "$data/profile.json" --map "$full/map.yaml" --initial-file "$sections/start.json" --out out/field-sections-track
}
```

Для нового прогона нужен свободный путь `$sections`. В нём сохраняются восемь карт и `report.json` с результатами всех попыток. При отказе или нескольких принятых частях файл позы отсутствует. Без `--grid-dll` построение частичных карт выполняется в Python.

**Проверка почти неподвижного робота.** На трёх следующих неперекрывающихся окнах по 60 сканов (первые кадры 2620, 2680 и 2740) тот же поиск по восьми сохранённым картам трижды отказал. Для карты начального участка в каждом окне все шесть сканов дали поддержанную глобальную позу, но изменение ракурса не достигло порога подтверждения движения. На остальных семи картах в каждом окне число принятых глобальных поз равнялось нулю. Проверены все 24 пары «окно и участок» и 144 отдельных кандидата. Ошибка стартовой позы здесь не определена. Окна относятся к одному посещению одного объекта. [Протокол №97](https://github.com/Ivana-banana/MGTS/issues/97)

```powershell
& $python -m tools.heap1_submap_holdout out/heap1-heldout-37 $sections out/field-sections-holdout
```

Для первого аргумента используйте набор из 180 сканов, подготовленный с `heap1_revisit.py --held-out`. Инструмент сохраняет решения всех попыток в `blind.json` до чтения опорной траектории. Для принятой позы `scored.json` дополнительно содержит ошибку относительно CPT7.
