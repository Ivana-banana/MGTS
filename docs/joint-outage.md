# Одновременный разрыв лидара и одометрии

В двух синтетических инспекциях обычная локализация пережила отсутствие обоих потоков, пока одометрия после возобновления сохранила прежнюю систему координат. Когда начало координат одометрии сбросилось, обычный режим потерял привязку до конца записи. На этом же входе `localize --recover` вернулся на карту через 0,30 с после первого нового скана. Внутри разрыва `continuous` не выдавал поз, опирающихся на устаревшую привязку.

| Сценарий | Ошибка XY первого скана в 255,035 с, см (seed 41 / 73) | Первая подтверждённая поза | Подтверждено из последних 50 сканов (41 / 73) |
|---|---:|---|---:|
| Чистая запись | 4,15 / 4,06 | 255,035 с | 50 / 50 |
| Пропал только лидар | 4,07 / 4,25 | 255,035 с | 50 / 50 |
| Совместный разрыв, прежнее начало координат | 4,07 / 4,25 | 255,035 с | 50 / 50 |
| Совместный разрыв и сброс начала координат | 150,89 / 150,42 | Не получена до конца записи | 0 / 0 |
| Та же запись со сбросом и `--recover` | 150,89 / 150,42 | 255,335 с | 47 / 47 |

В двух последних строках первый скан имел статус `prediction_only`. В режиме восстановления первая подтверждённая поза имела ошибку **3,87 см / 2,80 см**. Максимальная ошибка XY среди 47 подтверждённых после восстановления поз была 4,72 см / 4,52 см. Оба прогона зарегистрировали одну попытку и одно успешное восстановление.

## Что увидит потребитель траектории

В интервале отсутствия лидара при исправной одометрии `continuous.csv` содержал 40 прогнозов на реальных метках одометрии. При совместном выпадении оба seed дали только первые 10 прогнозов, последний в 253,450 с. Одометрия вернулась в 254,500 с. Между этой меткой и первым новым сканом предсказаний не было. При сохранении системы координат первая следующая строка была подтверждённой позой в 255,035 с, а при сбросе с включённым восстановлением — в 255,335 с.

Без восстановления после сброса непрерывная траектория закончилась в 253,450 с, за **6,485 с до последнего скана**. При этом файл `trajectory.csv` продолжался с прогнозами на метках лидара. Поэтому при разборе покрытия проверяйте последнюю метку каждого файла: максимум интервалов между уже записанными строками не учитывает отсутствующий хвост.

## Условия и повторение

Для каждого seed (41, 73) строится одна карта офиса с клеткой 8 см из неизменённого обхода. Все режимы используют эту карту и одинаковую известную стартовую позу инспекции. На копиях ROS 2 bag удаляются 20 сообщений лидара в интервале [3,0; 5,0) с от начала инспекции. В совместных сценариях удаляются также 20 сообщений одометрии в [3,5; 4,5) с. Между фактически соседними отсчётами одометрии получается 1,05 с при пороге профиля 0,35 с. IMU сохраняется.

При сбросе из всех последующих координат одометрии вычитается первое вернувшееся положение (1,57070; 0,07046) м. Оси, угол, имя кадра и временные метки сохраняются. Обычный прогноз на первом новом скане использует разность поз одометрии у двух наблюдаемых сканов; смена начала координат входит в эту разность. Проверена одна геометрия, две реализации шума и один момент сброса. Доверять такому прогнозу в новом здании до повторной привязки оснований нет.

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
& $python -m tools.evaluate_joint_outage out/joint-outage-new
& $python -m pytest -q tests/test_joint_outage.py tests/test_continuous.py tests/test_recovery.py
```

Команде нужен новый каталог. Внутри сохраняются исходные и изменённые bags, неизменная для вариантов карта каждого seed, отдельные `trajectory.csv`, `continuous.csv`, `summary.json` и общий `report.json`. Эталон используется только при оценке поз на совпадающих метках сканов. Пропущенные точки траектории для оценки не достраиваются.
