# Точность локализации: поверхность стен вместо центров клеток

На десяти синтетических парах записей средняя ошибка положения на чистой инспекции снизилась с **3,86 до 0,48 см** в офисе и с **1,52 до 0,63 см** в коридоре. Ошибка уменьшилась во всех 60 прогонах с полной дальностью лидара. При дальности 3 м изменение осталось в пределах разброса между seed. Время локализации сократилось на 7 %. Автостарт не изменился: 10 верных из 10. Реальные данные HEAP-1 в этом эксперименте не проверялись, их нет в локальной копии.

## Что изменено

Локализатор сопоставлял скан с центрами занятых клеток карты. Центры клеток описывают стену лесенкой со смещением до половины клетки. В офисе это давало почти постоянный сдвиг оценки примерно на 3,5 см по y, уже на первом скане при старте из эталонной позы. Разброс между seed составлял 0,03 см, то есть ошибка была систематической, а не шумовой. Карта обхода при этом точна: ATE обхода 0,88 см.

Теперь при загрузке карты для локализации каждая точка заменяется средним занятых клеток своей окрестности 3×3. Шаг сетки берётся как медианное расстояние между соседними точками карты. Функция `surface_points` в `mgts_nav/slam.py` применяется только к карте локализации. Построение карты, накопление клеток (в том числе нативное), формат `map.pgm`/`map.yaml`, CLI и автостарт не менялись.

## Условия

Для каждой раскладки генерируются пять пар обход/инспекция: офис с seeds 17, 101, 202, 303, 404 и коридор с seeds 41, 73, 505, 606, 707. Карта строится текущим трекером с клеткой 8 см. На каждой паре выполняется семь вариантов инспекции:

- чистая запись;
- четыре нарушения из `mgts_nav/stress.py`: пустые облака, пропавшие сообщения лидара, пропуск IMU и дрейф кинематики;
- лидар, ограниченный дальностью 3 м, как в [опыте с неоднозначностью](ambiguity.md);
- стартовая поза, смещённая на 0,15 м и −0,10 м с поворотом на 5°.

Старт инспекции задан эталонной позой, кроме варианта со смещённым стартом. Эталонная траектория используется только для оценки. Автостарт проверяется отдельно, по первому скану чистой записи. Позиция «верно» означает ошибку до 0,25 м и до 10°.

## Открытая проблема: офис при дальности 3 м

При дальности 3 м четыре офисных seed из пяти ещё до изменения молча уходили примерно на 60 см. Доля matched при этом оставалась около 0,97. В радиусе 3 м от маршрута видны только коробка и движущийся цилиндр. ICP на каждом шаге вносил небольшую поправку, и ошибка курса накапливалась до 21°. Изменение этот срыв не исправляет и не усиливает. На расходящихся прогонах доля matched снизилась с 0,964 до 0,900, поскольку больше уже неверных сопоставлений отклоняется. По seed ATE до изменения: 61,9 / 4,4 / 60,2 / 59,7 / 60,1 см, после — 61,9 / 3,1 / 61,3 / 61,4 / 61,8 см. В коридоре при той же дальности среднее улучшилось. Худший seed 41 изменился с 2,5 до 4,9 см при разбросе базовой линии ±5,8 см.

## Отвергнутые гипотезы

Изменение принималось только при двух условиях: ни один сценарий не ухудшается сверх разброса между seed, а среднее улучшается.

- **ICP «точка — прямая» с нормалями карты.** Поверх поверхности стен ATE на чистой записи в офисе снизилась до 0,33 см, RPE — на 35–50 %. При дальности 3 м в коридоре оценка скользила вдоль прохода: 26–86 см против 1,7–5,0 см у принятого варианта. Без поверхности стен изменение почти ничего не давало: в офисе 3,79–3,93 см.
- **Прогноз вместо ICP в слабо наблюдаемых направлениях.** Собственные числа информационной матрицы «точка — прямая» отделяют полный обзор (35–90 «эффективных точек») от обзора до 3 м (0–8). Отбрасывание или ослабление поправки по слабым направлениям сократило ошибку в офисе при 3 м с 50 до 1,6–3,3 см на всех пяти seed. В коридоре при 3 м ошибка выросла с 3,0 до 5,8–12,8 см, потому что вдоль коридора прогноз опирается на кинематику с масштабом 1,045. Это компромисс, который требует решения команды. Сначала стоит оценивать масштаб кинематики по принятым сопоставлениям.

## Воспроизведение

Запускайте из корня MGTS. Первая команда создаёт 20 записей в `out/accuracy/data`. Флаг `--cell-centres` восстанавливает сопоставление с центрами клеток. Обе серии используют одни и те же записи.

```powershell
python tools/accuracy_experiment.py out/accuracy/before --data out/accuracy/data --cell-centres
python tools/accuracy_experiment.py out/accuracy/after --data out/accuracy/data
python tools/accuracy_experiment.py out/accuracy --compare out/accuracy/before/results.json out/accuracy/after/results.json
python -m pytest -q tests/test_surface.py
```

Каждая серия занимает около 40 с. В `results.json` сохраняются строки по каждому seed и сценарию. В `results.md` собрана сводная таблица. Таблицы в [demo-results.md](demo-results.md) и [corridor.md](corridor.md) получены до этого изменения на версиях, указанных там через SHA-256.
