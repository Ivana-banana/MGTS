# Слепой старт на семи синтетических окнах

Проверена функция `estimate_start` из №32 (коммит `4cb6d99`). Она отказалась выдавать позу во всех семи окнах. Из них три содержали полный обзор на правильной карте. Офис и оба коридора показывают цену отказа даже при наличии ориентиров.

| Окно инспекции | Карта и обзор | Исход | Причина | Время поиска, с |
|---|---|---|---|---:|
| Офис 17, 0–50 | Своя, полный | Отказ | Глобальные позы расходятся с локальным движением | 1,75 |
| Офис 17, 0–50 | Чужая (коридор 41), полный | Отказ | Меньше трёх принятых глобальных поз | 1,38 |
| Коридор 41, 0–50 | Своя, полный | Отказ | Глобальные позы расходятся с локальным движением | 1,48 |
| Коридор 41, 30–80 | Своя, дальность до 3 м | Отказ | Меньше трёх принятых глобальных поз | 1,03 |
| Коридор 73, 0–50 | Своя, полный | Отказ | Глобальные позы расходятся с локальным движением | 1,46 |
| Коридор 73, 30–80 (3H) | Своя, дальность до 3 м | Отказ | Меньше трёх принятых глобальных поз | 1,08 |
| Прямоугольник, 0–50 | Симметричная, полный | Отказ | Меньше трёх принятых глобальных поз | 1,17 |

Итого 0 правильных стартов, 0 ложных, 7 отказов. Поскольку оценок позы нет, ошибка начальной позы для этих окон не определена. В частности, первый скан случая 3H ранее давал одиночному поиску ложный старт с ошибкой 5,94 м и 179,43°. Окно с тем же первым сканом дало отказ.

План окон зафиксирован до запуска. В каждом окне 51 последовательный скан, позиции для глобального поиска 0, 10, 20, 30, 40 и 50 относительно начала окна. Карты построены по отдельным записям обхода с разрешением 0,08 м. При чтении инспекции отключён топик одометрии, сохранены данные гироскопа. Ограничение дальности применяется к каждому скану относительно положения лидара. Эталон разрешено читать только после получения позы, для подсчёта правильных стартов установлены допуски 0,25 м и 10°. На чужой карте любое принятие считается ложным. В прямоугольнике траектория проходит больше 2 м, а её поворот на 180° вокруг центра комнаты даёт те же дальности.

Команда из корня MGTS в локальном Windows PowerShell:

```powershell
& .\.venv-mgts\Scripts\python.exe -m pytest -q -s tests/test_delayed_start_controls.py
```

Повтор на опубликованной реализации: 7 passed за 21,32 с с подготовкой карт. В таблице приведено время одного вызова поиска. Тест допускает будущие правильные старты на однозначных окнах и проверяет каждый принятый результат по эталону. Для чужой и симметричной карт обязателен отказ.

## Старт после разрыва в начале записи

Экспериментальная команда `tools.delayed_after_gap` ищет начало локализуемой части инспекции. Бюджет — до трёх окон по 51 скану. Только разрыв по времени или недостатку точек разрешает перейти к следующему окну: оно начинается с правого скана разрыва либо сразу после него, если в нём меньше 12 точек. При несогласии глобальных поз или слабой поддержке поиск завершается. Пороги подтверждения взяты из действующего delayed. [Протокол до прогона](https://github.com/Ivana-banana/MGTS/issues/151#issuecomment-7149936069)

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
& $python -X utf8 -m tools.delayed_after_gap data/inspection data/profile.json out/map/map.yaml out/after-gap --method keyframes
& $python -X utf8 -m pytest -q -s tests/test_delayed_start_controls.py -k after_gap
```

Метод `pairwise` сопоставляет соседние сканы, `keyframes` использует локальные ключевые сканы. При успехе код выхода 0, а `trajectory.csv` начинается с первого скана принятого окна. Его поза подтверждается с использованием более поздних сканов. В `report.json` поле `start_t` относится к началу окна, а `uncovered_t` перечисляет принятые на вход метки, оставшиеся без позы. При полном отказе код 3, сохраняется отчёт с причинами попыток и всеми непокрытыми метками.

| Данные | Результат с ключевыми сканами | Результат попарного метода |
|---|---|---|
| Офис, seed 17, все 100 сканов | Старт с 250,035 с, 100/100 matched, ошибка начальной позы 3,24 см и 0,081°, ATE 3,97 см | Отказ по несогласию глобальных поз |
| Тот же офис, удалены сканы 2–7 (индексы с нуля) | Старт с 250,835 с, 92/92 matched, ошибка начальной позы 2,22 см и 0,347°, ATE 3,98 см по покрытой части | После перехода через разрыв — отказ по несогласию глобальных поз |
| Симметричный прямоугольный коридор, тот же пропуск | Отказ во втором окне, менее трёх принятых глобальных поз | Тот же отказ |
| Intel Lab, инспекция №108, исходные 60 сканов | Три окна с индексов 0, 1 и 5 содержали разрывы; 60 меток без позы | Тот же отказ |

В офисе с пропуском поступили 94 скана: первые два (250,035 и 250,135 с) остались без позы, шесть удалённых меток отсутствовали на входе. Покрытие составило 92/94 поступивших и 92/100 исходных меток. Реальный вызов CLI на таком же прореженном ROS 2 bag дал тот же старт. На исходном потоке офис сравнивали с синтетическим эталоном только после поиска. Коридор проверяет один случай неоднозначности. Результат Intel относится к исходному окну и зафиксированному бюджету.

## Независимые карты после пропуска

Для четырёх сценариев из каждого исходного потока исключены сканы 2–7 (индексы с нуля). Оба метода получают одинаковые оставшиеся сканы, без одометрии инспекции. Пороги подтверждения и бюджет трёх окон сохранены. До запуска критерием допуска каждого метода к рассмотрению для штатного CLI выбраны ноль ложных стартов, верный старт HEAP-1 (до 0,25 м и 10°) и точный учёт непокрытых меток. [Протокол №152](https://github.com/Ivana-banana/MGTS/issues/152#issuecomment-7150055819)

Офис seed 29 проверен на чужой карте коридора seed 61. Для двух других контролей использована инспекция этого коридора: в одном к карте добавлена точная копия на +20 м по X, в другом оставлена только сдвинутая копия. Эталон сохраняет исходную систему координат. В полевом случае карта HEAP-1 построена на кадрах 150–189, инспекция взята из окна 2560–2619. [Подготовка записей HEAP-1](public-data.md)

```powershell
& .\.venv-mgts\Scripts\python.exe -X utf8 -m tools.post_gap_controls out/heap1-revisit-v2 out/post-gap-controls
```

Команда сохраняет использованные карты и report.json с попытками, индексами и метками. Ошибка старта и ATE относятся к исходной карте и покрытой части траектории соответственно. При полном отказе все поступившие метки перечислены в uncovered_t.

| Контроль | Попарный метод | Ключевые сканы | Полученные метки без позы, попарный / ключевые |
|---|---|---|---|
| Офис на чужой карте коридора | Отказ, недостаточно глобальных привязок | Та же причина | 94/94 и 94/94 |
| Коридор с двумя одинаковыми секциями | Отказ, недостаточно глобальных привязок | Та же причина | 94/94 и 94/94 |
| Только сдвинутая секция коридора | Отказ по несогласию глобальных поз | Ложный старт с ошибкой 19,996 м и 0,097°; 92/92 последующих сканов привязаны, ATE 20,019 м | 94/94 и 2/94 (2,13%) |
| Полевой повтор HEAP-1 | Верный старт, 8,53 см и 0,104°; ATE 4,81 см | Верный старт, 3,43 см и 0,298°; ATE 4,79 см | 2/54 и 2/54 (3,70%) |

На HEAP-1 старт обоих методов относится к метке 1731588668,881504 с (индекс 8 в исходной записи), все 52 последующих позы включая старт получили статус matched. Шесть удалённых сканов исключены из знаменателя. В коридоре с одной неверно размещённой копией метод ключевых сканов получил высокое покрытие в ошибочной глобальной системе координат.

На этих четырёх случаях попарный метод дал один верный старт и три отказа, выполнив зафиксированный критерий для рассмотрения в отдельной задаче. Метод ключевых сканов дал один верный старт, один ложный и два отказа; критерий для него не выполнен. По этим четырём зависимым сценариям нельзя оценить общую частоту ложных стартов.
