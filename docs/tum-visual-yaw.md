# Оценка поворота камеры на TUM RGB-D

На записи Freiburg 1 rpy камера Kinect двигалась в помещении под наблюдением внешней системы захвата движения. Из 72 коротких пар штатная оценка приняла 24 (33,3%). На принятых парах ошибка локального курса составила 0,090° RMS, максимальная абсолютная — 0,217°. Только три принятых пары имели модуль эталонного курса не менее 1°. Результат ограничен малыми поворотами, сценой и доступностью внешних измерений переноса и глубины.

## Вход и геометрия

Использованы исходные 723 цветных кадра, зарегистрированная глубина Kinect и groundtruth.txt из архива RGB-D SLAM Dataset and Benchmark (J. Sturm и соавторы, TUM). До измерения зафиксированы начальные индексы 0, 10, …, 710 и два конечных индекса для каждого начала: i+1 и i+6. RGB-интервалы допускались соответственно до 100 и 400 мс. Позиции в метрах интерполированы линейно, ориентации xyzw — сферической интерполяцией между двумя соседними измерениями mocap с разрывом до 40 мс. [Запись Freiburg 1 rpy](https://webshare.cvg.cit.tum.de/g/rgbd/dataset/) · [Описание форматов и калибровка TUM](https://cvg.cit.tum.de/data/datasets/rgbd-dataset/file_formats) · [Протокол до расчётов](https://github.com/Ivana-banana/MGTS/issues/153#issuecomment-7150126853)

Из исходного RGB получено ректифицированное изображение с тем же K. Для каждого выходного пикселя по модели Brown–Conrady вычислена позиция в исходном кадре и яркость интерполирована билинейно. Применены опубликованные для Freiburg 1 параметры fx/fy 517,3/516,5, cx/cy 318,6/255,3 и пять коэффициентов дисторсии. Патчи, пересекающие границу доступного изображения, исключены. Поиск признаков, сопоставление и оценка поворота выполнены функциями MGTS.

Поза C в эталоне переводит оптические координаты RGB в координаты мира. Оптические оси направлены вправо, вниз и вперёд. Для условной базы с осями вперёд, влево и вверх используется постоянная матрица M, у которой строки (0,0,1), (−1,0,0), (0,−1,0). Эталон приращения равен D = M C₀ᵀ C₁ Mᵀ, где C₀ и C₁ — матрицы вращения; курс равен atan2(D₁₀,D₀₀). Изображения задают обратное относительное вращение лучей. В независимой аналитической проверке на 16 ориентирах получены правильные знаки для −10°, 0° и +10°. Здесь измеряется локальный поворот условной базы камеры, установка камеры на роботе не калибровалась.

Для проверки параллакса использовано смещение оптического центра по mocap с добавкой 2 мм. Для каждой точки первого кадра берётся соответствующая координата в исходном RGB и ближайшая зарегистрированная карта глубины с разницей до 20 мс. Требуются девять ненулевых глубин в окрестности 3×3; нижняя оценка дальности равна минимальной осевой глубине среди оставшихся признаков минус 10 см. Эти запасы — экспериментальные допущения. Точность регистрации глубины, задержка датчиков и движение объектов могут нарушать полученные границы. Из mocap в оцениватель передаётся только скалярная граница переноса; внешний курс используется для последующего сравнения.

## Покрытие и отказы

| Исход | Соседние кадры | Через шесть кадров |
|---|---:|---:|
| Приняты | 24 | 0 |
| Возможен параллакс | 45 | 67 |
| Недостаточно треков | 0 | 4 |
| Слабое согласие вращения | 1 | 0 |
| Неплоский поворот по изображению | 1 | 0 |
| Нет подходящей скобки времени mocap | 1 | 1 |

Длинные пары служат контролем смешанного движения. У всех 71 длинных пар с допустимой привязкой времени оценка возможного параллакса превысила 0,35°, у 56 также внешний наклон превысил 3°. Причины в таблице соответствуют первой сработавшей проверке. Для длинных пар ошибка курса не определена.

У коротких пар с допустимой привязкой времени 11 нарушили критерий наклона по mocap. Из них оцениватель принял одну пару, индекс 670: внешний наклон 3,136°, ошибка курса −0,023°. На остальных 23 принятых парах, удовлетворивших обоим внешним критериям, ошибка составила 0,092° RMS. Эталонный курс на всех принятых парах лежал от −1,670° до +1,303°. Ни одна принятая пара не превысила предел по оценённому параллаксу.

## Воспроизведение

В локальном Windows PowerShell из корня MGTS. SHA-256 исходного TGZ — 78103722a25873dbbb4de027eaa8c810a6382100691f02b6cf95c3adc91c4ac1. Сценарий записывает ректифицированные пары с треками в pairs.jsonl и результаты по каждому интервалу в results.json. Для повторного прогона нужен новый каталог результата.

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
New-Item -ItemType Directory -Force out/tum-source | Out-Null
curl.exe -fL 'https://cvg.cit.tum.de/rgbd/dataset/freiburg1/rgbd_dataset_freiburg1_rpy.tgz' -o out/tum-source/fr1-rpy.tgz
Get-FileHash out/tum-source/fr1-rpy.tgz
tar -xf out/tum-source/fr1-rpy.tgz -C out/tum-source
& $python -m tools.tum_visual_yaw out/tum-source/rgbd_dataset_freiburg1_rpy out/tum-rpy-result
```
