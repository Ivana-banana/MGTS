# Повторное посещение внутри обхода

Команда читает bag обхода и `trajectory.csv` от штатного `map`. В JSON каждое подтверждение содержит индексы сканов с нуля, время заголовков в секундах, меньшую из двух долей совпадающих точек и оценённое ICP расстояние между позициями. Несколько пар могут описывать одно посещение. Команда выводит диагностику в stdout; построение карты и оптимизация графа поз остаются отдельными операциями.

```powershell
python -m mgts_nav.interior_loop data/mapping out/official-01/map/trajectory.csv --config data/mapping.json
python -m pytest -q -s tests/test_interior_loop.py tests/test_loop.py
```

Для каждой метки проверяется соответствие строки CSV скану с допуском 1 мс. По умолчанию поиск рассматривает каждый пятый скан, хранит до 64 подтверждённых сканов по 512 точек и выполняет не более 64 вызовов ICP за обход. Это до 512 КиБ для сохранённых координат float64, сверх которых расходуется память загрузчика, текущего скана, индексов и временных массивов. Параметры `--stride`, `--history` и `--budget` задают эти пределы. При частоте 10 Гц и сплошных подтверждениях история охватывает около 32 с. Проверки начинаются с первых подходящих пар по ходу движения; для одного нового скана приоритет у ближайшей предыдущей позы.

Кандидат требует интервала от 4 с, удаления от старой позы минимум на 2 м и возвращения по оценённой траектории в радиус 1 м. Порог ICP для расстояния между позициями — 0,45 м; доля соответствий в радиусе 0,16 м должна достигнуть 70% в каждом направлении. Для проверки периодичности алгоритм пробует сдвиги ±1, ±2 и ±3 м вдоль главной оси старого облака. Альтернатива считается неоднозначной, если в общей области обзора осталось от 70% точек каждого скана, а её двусторонняя поддержка достигает 70% и отстаёт от основной максимум на 5 процентных пунктов.

## Контрольные маршруты

Офисные проверки запускают `map` и диагностическую команду на детерминированных записях по 200 сканов. Эталон генератора используется только в тесте. В положительном случае робот проходит через точки (2,4; 0) и (2,4; 2) м, возвращается к началу, затем заканчивает обход в точке (−2; 1) м.

| Сценарий | Проверено геометрически | Принятые пары | Ложные пары |
|---|---:|---:|---:|
| Возврат внутри обхода | 48 | 13 для одного возврата | 0 при проверке расстояния по эталону ≤0,50 м |
| Прямой маршрут длиной 4,3 м | 0 | 0 | 0 |
| Периодический коридор с ошибочно сближенными позами | 6 | 0 | 0 |

В офисе отобрано 40 сканов из 200. На маршруте с возвратом 35 из 48 пар отклонены по геометрии. На прямом маршруте 252 пары оказались слишком близкими по времени, 492 — слишком далёкими по положению, ещё 36 не имели достаточного промежуточного ухода. Диагностический CLI с чтением bag занял 0,99 и 0,84 с соответственно на локальной Windows. В коридорном контроле из восьми искусственных сканов три пары отклонены из-за периодичности и три по геометрии. При сокращении бюджета до двух проверок ещё четыре пары отражены в `skipped_budget`.

Счётчики JSON также показывают пропуски по шагу выборки, неподтверждённым позам или недостатку точек и вытеснение из истории. При большом дрейфе поз истинный возврат может оказаться за радиусом поиска. Короткий возврат между выбранными сканами, возврат к вытесненному скану и совпадения после исчерпания бюджета могут быть пропущены. Шесть проверяемых сдвигов охватывают лишь часть симметрий сцены. На официальных записях качество пока не измерялось.
