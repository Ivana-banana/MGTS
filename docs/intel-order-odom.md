# Intel Lab: совместная проверка сортировки IPC и колёсной одометрии

На временных границах №107 сравниваются четыре сочетания двух изменений. Сортировка IPC возвращает опоздавшие FLASER в последовательность по их исходным меткам. Колёсная одометрия добавляет измеренные ODOM к тем же лазерным сообщениям. Для каждого сочетания заново построена карта с разрешением 8 см и запущены две инспекции — delayed и с одинаковой переданной стартовой позой. Выбор окон и внешняя стартовая поза описаны в [исходном эксперименте](intel-lab.md). [Протокол до прогона](https://github.com/Ivana-banana/MGTS/issues/112#issuecomment-7149147477)

## Покрытие

В обоих порядках обход длится 186,719 с, инспекция — 15,456 с. Ни первая, ни последняя метка каждого окна не изменилась. Дубликатов FLASER в выбранных строках нет. Колёсное покрытие скана требует двухсторонней интерполяции на его метке. Для покрытия разрыва проверена вся цепочка ODOM от одной лазерной метки до другой с максимальным интервалом 0,5 с. В таблице приведены все лазерные интервалы длительнее штатного предела delayed 0,35 с.

| Окно | Порядок | Сканы с покрытием ODOM | Разрывы с покрытием ODOM / всего |
|---|---|---:|---:|
| Обход | Исходный контроль №107 | 744/824 | 132/214 |
| Обход | По IPC | 849/943 | 135/214 |
| Инспекция | Исходный контроль №107 | 49/60 | 8/20 |
| Инспекция | По IPC | 65/78 | 8/19 |

В первых 51 сканах инспекции после сортировки осталось 11 длинных интервалов, из них только четыре целиком покрыты ODOM. До сортировки их было 17, из них покрыты шесть. Первый интервал в обоих случаях длится 0,532869 с. У самой первой метки интервал между соседними отсчётами ODOM равен 0,532837 с, поэтому колёсного покрытия здесь тоже недостаточно. Штатный delayed проверяет непрерывность лазерной цепочки до выбора глобальных опор.

## Воспроизведение

Из корня MGTS в Windows PowerShell. Нужны исходный архив №107 и профиль с /odom, подготовленный адаптером №108. Результаты всех четырёх вариантов и сведения по каждому разрыву сохраняются в новом каталоге.

```powershell
$p = '.\.venv-mgts\Scripts\python.exe'
& $p -m tools.intel_order_odom out/intel107/intel.log.gz out/intel108/data out/intel112
& $p -m pytest -q tests/test_intel_order_odom.py tests/test_intel_lab.py tests/test_intel_laser_clock.py
```

## Результаты

| Порядок и датчики | Обход: matched / prediction_only после origin | Расхождение XY с RBPF, обход (50 эпох) | Инспекция с заданным стартом | Расхождение XY с RBPF, инспекция (4 эпохи) |
|---|---:|---:|---:|---:|
| Исходный контроль, лидар | 796 / 27 | 4,972 м | 60/60 matched | 2,411 м |
| Исходный контроль, лидар + ODOM | 647 / 176 | 0,728 м | 60/60 matched | 0,402 м |
| По IPC, лидар | 911 / 31 | 4,321 м | 78/78 matched | 2,392 м |
| По IPC, лидар + ODOM | 912 / 30 | 0,504 м | 78/78 matched | 0,235 м |

Каждый столбец расхождений — среднеквадратичное расстояние XY на одних и тех же проверенных метках, без интерполяции между эпохами и без подгонки поз. Для обоих порядков метки и байты всех FLASER совпали при добавлении ODOM. Четыре контрольных CSV обхода и инспекции побайтово совпали с №107 и №108.

Совместная обработка дала наименьшее расхождение на обоих окнах. По сравнению с исходным контролем с ODOM сортировка снизила его ещё на 0,223 м на обходе и 0,167 м на инспекции. Во всех четырёх случаях delayed завершился кодом 2 с причиной Gap in the local scan chain и пустым списком опор. RBPF построен по той же записи. Независимой оценки абсолютной ошибки для этих меток нет.
