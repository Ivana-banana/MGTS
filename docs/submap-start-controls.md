# Слепой старт по участкам карты на демоданных

Все 12 решений дали отказ. На своей карте принято 0 из 8 стартов, на чужой — 0 из 4. При полном обзоре на своей карте каждый из 20 участков дал как минимум три опоры, но их оценки исходной позы разошлись после учёта локального движения. В этих окнах разбиение обхода на части не дало рабочего начального положения. [План до измерения](https://github.com/Ivana-banana/MGTS/issues/95#issuecomment-7148576868)

Для каждой карты трекер один раз прошёл 200 сканов обхода с обычной конфигурацией демо. Из поз этого единого трека построены пять растров с клеткой 8 см. Столбцы ниже перечисляют исходы по порядку начала участка — 0, 40, 80, 120, 160. **Р** означает расхождение глобальных опор с локальным движением, **М** — принято менее трёх опор, **Ц** — отказ при проверке цепочки локальных сканов. Для офиса окно инспекции 0–50, для коридора 30–80 включительно.

| Инспекция | Карта обхода | Полный обзор, по участкам | Радиус 3 м, по участкам |
|---|---|---|---|
| Офис 17 | Офис 17 | Р Р Р Р Р | М Р Р М М |
| Офис 29 | Офис 29 | Р Р Р Р Р | Ц Ц Ц Ц Ц |
| Коридор 41 | Коридор 41 | Р Р Р Р Р | М М М М М |
| Коридор 73 | Коридор 73 | Р Р Р Р Р | М М М М М |
| Офис 17 | Коридор 41 | М М М М М | М Р М М М |
| Офис 29 | Коридор 41 | М М М М М | Ц Ц Ц Ц Ц |

Условие принятия — ровно один участок с успешным штатным `delayed` в режиме `pairwise`. Здесь все участки отказали по отдельности. Правило разрешения нескольких успехов ни разу не понадобилось. Ошибка принятой позы поэтому отсутствует. Нулевое число ложных стартов при одновременном отказе всех положительных контролей не позволяет судить о точности принятых стартов.

Инспекция использовала сканы и гироскоп. Радиус ограничивали только на инспекции, относительно начала лидара. В рамках одной планировки seed меняет шум и пропуски измерений при одной геометрии и траектории. Для чужой карты брали другую планировку. Эталон разрешён только после единственного успеха на своей карте, для проверки XY ≤ 0,25 м и угла ≤ 10°. В этом прогоне чтение эталона не потребовалось.

Для воспроизведения из корня MGTS в Windows PowerShell:

```powershell
& .\.venv-mgts\Scripts\python.exe -m pytest -q -s tests/test_submap_controls.py
```

Каждое окно выводит отдельную строку JSON с решениями по всем участкам.

## Повтор с ключевыми кадрами

В №98 изменили только способ оценки локального движения в `delayed`. На четырёх окнах со своей картой и полным обзором каждый из пяти участков дал позу. Максимальные попарные расхождения во всех четырёх наборах уложились в заранее выбранные 20 см и 6°. При правиле единственного успеха все четыре решения остаются отказами. [План сравнения](https://github.com/Ivana-banana/MGTS/issues/98#issuecomment-7148663092)

| Своя карта, полный обзор | Успешные участки, pairwise / keyframes | Максимальный разброс XY, см | Максимальный разброс курса, ° |
|---|---:|---:|---:|
| Офис 17 | 0 / 5 | 4,37 | 0,511 |
| Офис 29 | 0 / 5 | 7,17 | 0,403 |
| Коридор 41 | 0 / 5 | 3,84 | 0,094 |
| Коридор 73 | 0 / 5 | 4,47 | 0,030 |

В остальных восьми окнах обе версии получили по нулю успешных участков. Итог каждой версии — 0 верных, 0 ложных, 12 отказов. Несколько совместимых ответов возникли в 4 из 12 окон с ключевыми кадрами и в 0 из 12 при попарном сопоставлении. По этим четырём отказам эталон не открывался, поэтому близость пяти поз характеризует их согласованность, а абсолютная точность неизвестна.

### Полевой возврат HEAP-1

На восьми сохранённых растрах №94 обе версии приняли только участок 0–39. Семь остальных не набрали трёх опор. Ошибка начальной позы по CPT7 составила 13,84 см и 1,22° для `pairwise`, 18,54 см и 1,84° для `keyframes`. Обе позы проходят пороги оценки 25 см и 10°. При продолжении по одной полной карте на кадрах 2560–2619 обе версии сопоставили 60 из 60 сканов. Среднеквадратичная ошибка XY составила соответственно 6,30 и 6,29 см. Выигрыша в точности начальной позы на этом возврате не наблюдалось.

Демопроверка запускается командой выше. Полевой тест читает восемь карт из `out/issue94` и инспекцию из `out/heap1-long-80`. Если они отсутствуют, pytest помечает тест как пропущенный. Полный трек воспроизводится командой `mgts_nav localize` по карте №88 с `--initial 1.1411765080869758 1.2822107891343082 -0.047363773612197416` и профилем №80.

## Объединение согласованных поз

В №101 изменили правило принятия. При нескольких успешных участках проверили каждую пару поз. Если расстояние XY не превышало 20 см, а разница курса по короткой дуге — 6° у всех пар, результатом стали медианы координат X и Y и круговое среднее курса. При единственном успехе его поза принималась напрямую. Эталон читали только для оценки готового решения. [Протокол до прогона](https://github.com/Ivana-banana/MGTS/issues/101#issuecomment-7148763552)

На тех же 12 окнах с ключевыми кадрами объединение дало **4 верных старта, 0 ложных, 8 отказов**. Прежнее правило на них дало 12 отказов. Все четыре принятые позы получены на своей карте при полном обзоре. Оба режима просмотра чужой карты и все окна с ограничением дальности дали отказ.

| Инспекция | Ошибка XY, см | Ошибка курса, ° |
|---|---:|---:|
| Офис 17 | 2,29 | 0,121 |
| Офис 29 | 3,25 | 0,229 |
| Коридор 41 | 1,92 | 0,077 |
| Коридор 73 | 1,77 | 0,036 |

Два дополнительных отрицательных контроля использовали новое офисное окно с seed 53. Для карты 0–39 реальный поиск выдал две одинаковые по курсу позы на расстоянии 8 м друг от друга, когда исходный растр и его копия с переносом начала по X на +8 м предъявлялись вместе. Правило дало отказ. Когда предъявили только сдвинутый растр, поиск принял **ложный старт с ошибкой 8,008 м** при ошибке курса всего 0,036°. Всего в 14 решениях получилось 4 верных, 1 ложное и 9 отказов. Проверка согласия обнаруживает конфликт между ответами, но для единственного ответа свидетельства конфликта нет. Физически неверная система координат может дать точное локальное совпадение геометрии.

```powershell
& .\.venv-mgts\Scripts\python.exe -m pytest -q -s tests/test_submap_controls.py -k '((blind_sections and keyframes) or duplicate or consensus_checks)'
```
