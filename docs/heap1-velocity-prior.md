# Ограниченный прогноз переноса на длинном обходе HEAP-1

На тех же 300 сканах, что в №80, прогноз постоянной скорости снизил ATE обхода с 39,23 до 18,05 см, а ошибку положения в последней точке с 62,70 до 24,67 см. Новый прогноз менял только начальное приближение для ICP при построении карты. На повторной инспекции с заданным стартом штатный локализатор точнее прошёл по полученной карте. Слепой delayed отказался на обеих картах.

| Этап и показатель | Штатный нулевой перенос | Постоянная скорость корпуса |
|---|---:|---:|
| Обход, статусы | 1 origin, 299 matched | 1 origin, 299 matched |
| Обход, ATE / максимум / последняя ошибка XY, см | 39,23 / 62,70 / 62,70 | 18,05 / 28,00 / 24,67 |
| Обход, RMSE курса, ° | 0,620 | 0,245 |
| Инспекция с известным стартом | 60/60 matched | 60/60 matched |
| Инспекция, ATE / максимум / последняя ошибка XY, см | 32,62 / 38,64 / 32,15 | 6,29 / 11,08 / 8,54 |
| Инспекция, RMSE курса, ° | 0,799 | 0,356 |
| Слепой старт, принятые опоры | 0/6 | 0/6 |

На обеих картах причиной каждого отказа была слабая геометрическая поддержка. Максимальная оценка опоры выросла с 0,460 до 0,509 при штатном пороге 0,55. Эти данные поддерживают дальнейшую проверку режима как эксперимента. Для включения по умолчанию одного маршрута недостаточно, а слепая повторная инспекция по длинной карте по-прежнему не стартовала.

## Как получен прогноз

Алгоритм использует только две последние подряд подтверждённые позы со статусом matched. Их разность XY переводится в оси корпуса на момент более раннего скана и делится на интервал времени. Полученная скорость корпуса, включая боковую составляющую, переносится на новый интервал с учётом курса последней принятой позы. Длина шага ограничена меньшим из 0,20 м и 1,5 м/с × dt. После пропуска более 0,25 с, повторной или убывающей метки либо prediction_only история сбрасывается. Первые две свежие привязки заново задают скорость. Гироскоп используется штатно. На обходе прогноз сработал 297 раз. [Правило до запуска](https://github.com/Ivana-banana/MGTS/issues/88#issuecomment-7148401012)

Все параметры заданы до оценки. Обход — кадры 150–449, одна исходная поза в нуле, карта 0,08 м. Обе карты проверены на тех же кадрах инспекции 2560–2619 штатным delayed без эталона и отдельно с одной и той же первой позой CPT7. Остальные позы CPT7 использованы только для оценки. [Исходный обход](heap1-long-mapping.md)

## Синтетические контроли и воспроизведение

Для статической сцены из 180 точек заданы боковое движение на 0,48 м и последующая остановка. Обе версии сопоставили все 23 скана после origin. RMSE XY во время движения составила 0,059 мм, после остановки 0,063 мм в обоих вариантах. Здесь точки видны полностью, шум отсутствует. Отдельно проверены поворот корпуса на 90°, неравные интервалы, предел шага и восстановление после разрыва или отказа ICP.

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
& $python -m pytest -q -s tests/test_velocity_prior.py
& $python -m tools.heap1_velocity_prior out/heap1-long-80 out/heap1-long-score-80-repeat/map out/heap1-velocity-repeat
```

Сценарий запускается из корня MGTS в новый выходной каталог и использует сохранённую штатную карту и траекторию №80. Карта, CSV экспериментального обхода, результаты инспекций и scores.json остаются в выходном каталоге.

## Запуск через map и solve

Экспериментальный флаг `--mapping-velocity-prior` включает прогноз только на обходе. По умолчанию он выключен. При наличии одометрии трекер использует штатный кинематический прогноз. При её отсутствии две подтверждённые привязки дают прогноз переноса, а приращение курса по-прежнему берётся из гироскопа, если доступно. При резком изменении скорости прогноз может ошибаться. ICP проверяет совпадение с геометрией обычным способом.

```powershell
$python = '.\.venv-mgts\Scripts\python.exe'
$data = 'out/heap1-long-80'
& $python -m mgts_nav map "$data/mapping" --config "$data/profile.json" --resolution .08 --mapping-velocity-prior --out out/velocity-map
& $python -m mgts_nav.solve "$data/mapping" "$data/inspection" --config "$data/profile.json" --resolution .08 --mapping-velocity-prior --initial 0.9579082508672263 1.254084931557723 -0.015250987212696908 --out out/velocity-solve
```

Число применений прогноза записывается в `mapping_velocity_prior_steps` в сводке карты при включённом флаге. Команда `solve` передаёт флаг только в `map`. Пример использует известный старт инспекции из полевого контроля №88.
